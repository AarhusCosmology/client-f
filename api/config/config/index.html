class config.config.DerivedConfig#

The derived-parameter emulator: x -> (derived_1, …, derived_k).

A separate network from the log-likelihood one, because the problem is different: smooth regression of a few quantities with no peak and no dynamic range to speak of, so a plain mean-squared error on standardised outputs rather than msre. Its inputs are only the parameters the derived ones can depend on (inputs: auto), which for CLASS-derived quantities means the cosmological parameters alone – 6 of 27 on Planck. Give a list of names to override, or all.

Annealing is the default here, unlike for the log-likelihood network: the concern recorded under TrainingConfig.lr_schedule is msre on a sparse iteration-0 design, which does not arise for this loss.

Present in a run YAML, the emulator is retrained every iteration, so a likelihood on derived parameters can use it while sampling; absent, it is trained on demand by python client.py derived RUN_DIR with these defaults.

3 x 256 from a sweep over 2/3/4 layers x 64/128/256 neurons, three seeds each, on the it3 data (8298 points) of the Planck NPIPE TT LambdaCDM run, scored as held-out error in units of the published Planck+DESI widths. Width mattered more than depth. 3 x 256 had the lowest error on the hardest parameter, 100 theta_s (2.1% of sigma in the high-likelihood core, against 3.6% at 3 x 128), the smallest seed-to-seed spread there, and the lowest worst-case error over the whole box (11% of sigma). A fourth layer did not help (2.6%). It costs 81 s to train on those 8298 points, and about an eighth of the log-likelihood network’s cost per evaluation.
